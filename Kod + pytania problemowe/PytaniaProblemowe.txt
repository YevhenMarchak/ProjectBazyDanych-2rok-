1. Premia dla pracowników za obsłużone wysyłki
Opis problemu:
Firma chce przyznać premię pracownikom w zależności od liczby wysyłek obsłużonych w danym miesiącu.

Kroki:
1.Wyszukać pracowników, którzy realizowali wysyłki w danym miesiącu.
2.Policzyć liczbę wysyłek dla każdego pracownika.
3.Na podstawie liczby wysyłek wyznaczyć procent premii.

CREATE OR REPLACE FUNCTION calculate_employee_bonus(
    p_month INT,
    p_year INT
)
RETURNS TABLE(employee_id BIGINT, shipments_count INT, bonus_percent INT)
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN QUERY
    SELECT
        s.employee_id,
        COUNT(s.shipment_id)::INT,
        CASE
            WHEN COUNT(s.shipment_id) > 100 THEN 30
            WHEN COUNT(s.shipment_id) BETWEEN 50 AND 100 THEN 15
            ELSE 0
        END
    FROM shipments s
    WHERE EXTRACT(MONTH FROM s.shipment_date) = p_month
      AND EXTRACT(YEAR FROM s.shipment_date) = p_year
    GROUP BY s.employee_id;
END;
$$;

Wywolanie:
SELECT * 
FROM calculate_employee_bonus(10, 2024);

2. Automatyczne oznaczanie przeterminowanych wysyłek
Opis problemu:
Wysyłki starsze niż 7 dni i niezrealizowane powinny zostać automatycznie oznaczone jako przeterminowane.

Kroki:
1.Wyszukać wysyłki starsze niż 7 dni.
2.Sprawdzić ich aktualny status.
3.Zaktualizować status na OVERDUE.

CREATE OR REPLACE PROCEDURE mark_overdue_shipments()
LANGUAGE plpgsql
AS $$
BEGIN
    UPDATE shipments
    SET status = 'OVERDUE'
    WHERE shipment_date < CURRENT_DATE - INTERVAL '7 days'
      AND status <> 'DELIVERED';
END;
$$;

Wywolanie:
CALL mark_overdue_shipments();

CREATE OR REPLACE FUNCTION find_low_stock_products(
    p_min_quantity NUMERIC
)
RETURNS TABLE(
    product_id BIGINT,
    location_id BIGINT,
    quantity NUMERIC
)
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN QUERY
    SELECT
        i.product_id,
        i.location_id,
        i.quantity
    FROM inventory i
    WHERE i.quantity < p_min_quantity;
END;
$$;

4. Obliczenie stopnia realizacji dostawy
Opis problemu:
Chcemy określić procent realizacji danej dostawy (receipt).

Kroki:
1.Pobranie expected_quantity i received_quantity.
2.Zsumowanie ilości dla całej dostawy.
3.Obliczenie procentu realizacji.

CREATE OR REPLACE FUNCTION receipt_completion_percentage(
    p_receipt_id BIGINT
)
RETURNS NUMERIC
LANGUAGE plpgsql
AS $$
DECLARE
    expected_sum NUMERIC;
    received_sum NUMERIC;
BEGIN
    SELECT SUM(expected_quantity), SUM(received_quantity)
    INTO expected_sum, received_sum
    FROM receipt_details
    WHERE receipt_id = p_receipt_id;

    IF expected_sum = 0 THEN
        RETURN 0;
    END IF;

    RETURN (received_sum / expected_sum) * 100;
END;
$$;

Wywolanie:
SELECT receipt_completion_percentage(5);

5. Najaktywniejsi klienci w danym okresie
Opis problemu:
Firma chce zidentyfikować klientów generujących największą liczbę wysyłek.

Kroki:
1.Pobranie wysyłek z danego okresu.
2.Zliczenie wysyłek dla klientów.
3.Wybranie klientów przekraczających ustalony próg.

CREATE OR REPLACE FUNCTION get_top_clients(
    p_from DATE,
    p_to DATE,
    p_min_shipments INT
)
RETURNS TABLE(
    client_id BIGINT,
    shipments_count INT
)
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN QUERY
    SELECT
        s.client_id,
        COUNT(s.shipment_id)::INT
    FROM shipments s
    WHERE s.shipment_date BETWEEN p_from AND p_to
    GROUP BY s.client_id
    HAVING COUNT(s.shipment_id) >= p_min_shipments;
END;
$$;


Wywolanie:
SELECT *
FROM get_top_clients('2024-01-01', '2024-12-31', 1);

6. Kontrola pojemności lokalizacji magazynowej
Opis problemu:
System powinien sprawdzić, czy dana lokalizacja magazynowa nie została przepełniona.

Kroki:
1.Zsumowanie ilości produktów w lokalizacji.
2.Pobranie maksymalnej pojemności lokalizacji.
3.Porównanie wartości i zwrócenie wyniku.

CREATE OR REPLACE FUNCTION check_location_capacity(
    p_location_id BIGINT
)
RETURNS BOOLEAN
LANGUAGE plpgsql
AS $$
DECLARE
    total_quantity NUMERIC;
    v_max_capacity NUMERIC;
BEGIN
    SELECT SUM(i.quantity)
    INTO total_quantity
    FROM inventory i
    WHERE i.location_id = p_location_id;

    SELECT l.max_capacity
    INTO v_max_capacity
    FROM locations l
    WHERE l.location_id = p_location_id;

    RETURN total_quantity <= v_max_capacity;
END;
$$;


Wywolanie:
SELECT check_location_capacity(1);

7. Aktualizacja stanu magazynu po przyjęciu dostawy
Opis problemu:
Po przyjęciu dostawy system musi zaktualizować stany magazynowe.

Kroki:
1.Pobranie danych z receipt_details.
2.Dopasowanie produktów do inventory.
3.Aktualizacja ilości i daty modyfikacji.

CREATE OR REPLACE PROCEDURE update_inventory_after_receipt(
    p_receipt_id BIGINT
)
LANGUAGE plpgsql
AS $$
BEGIN
    UPDATE inventory i
    SET quantity = i.quantity + rd.received_quantity,
        last_updated = NOW()
    FROM receipt_details rd
    WHERE rd.receipt_id = p_receipt_id
      AND rd.product_id = i.product_id;
END;
$$;

Wywolanie:
CALL update_inventory_after_receipt(1);

8. Ocena produktywności pracowników
Opis problemu:
Chcemy określić produktywność pracowników na podstawie liczby obsłużonych klientów.

Kroki:
1.Pobranie wysyłek pracowników.
2.Zliczenie unikalnych klientów.
3.Określenie poziomu produktywności.

CREATE OR REPLACE FUNCTION employee_productivity()
RETURNS TABLE(
    employee_id BIGINT,
    clients_count INT,
    productivity_level TEXT
)
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN QUERY
    SELECT
        s.employee_id,
        COUNT(DISTINCT s.client_id)::INT AS clients_count,
        CASE
            WHEN COUNT(DISTINCT s.client_id) > 20 THEN 'HIGH'
            WHEN COUNT(DISTINCT s.client_id) BETWEEN 10 AND 20 THEN 'MEDIUM'
            ELSE 'LOW'
        END AS productivity_level
    FROM shipments s
    GROUP BY s.employee_id;
END;
$$;


Wywolanie:
SELECT *
FROM employee_productivity();

9. Najczęściej wysyłane produkty
Opis problemu:
Firma chce zidentyfikować produkty kluczowe pod względem wysyłek.

Kroki:
1.Pobranie danych z shipment_details.
2.Zsumowanie wysyłanych ilości.
3.Wybranie produktów przekraczających próg.

CREATE OR REPLACE FUNCTION most_shipped_products(
    p_min_quantity NUMERIC
)
RETURNS TABLE(
    product_id BIGINT,
    total_quantity NUMERIC
)
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN QUERY
    SELECT
        sd.product_id,
        SUM(sd.quantity_to_ship) AS total_quantity
    FROM shipment_details sd
    GROUP BY sd.product_id
    HAVING SUM(sd.quantity_to_ship) >= p_min_quantity;
END;
$$;


Wywolanie:
SELECT *
FROM most_shipped_products(1000);

10. Walidacja poprawności dostawy
Opis problemu:
System powinien sprawdzić poprawność danych dostawy przed jej zatwierdzeniem.

Kroki:
1.Pobranie danych o ilościach oczekiwanych i odebranych.
2.Sprawdzenie poprawności danych.
3.Zgłoszenie błędu lub zatwierdzenie dostawy.

CREATE OR REPLACE FUNCTION validate_receipt(
    p_receipt_id BIGINT
)
RETURNS BOOLEAN
LANGUAGE plpgsql
AS $$
BEGIN
    IF EXISTS (
        SELECT 1
        FROM receipt_details
        WHERE receipt_id = p_receipt_id
          AND received_quantity > expected_quantity
    ) THEN
        RETURN FALSE;
    END IF;

    RETURN TRUE;
END;
$$;

Wywolanie:
SELECT validate_receipt(12);
